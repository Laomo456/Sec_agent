### ★ 档位判据（比厂商名更重要）—— 同一家厂商，免费版 ≠ 企业版

**看到厂商名不等于企业级**，同一厂商分级，识别特征完全不同：

| 档位 | 保护 | 识别特征 |
|---|---|---|
| **免费版 / 个人版** | 只做 DEX 抽壳 | `libjiagu.so` **但无 `ffi_*` 导入** → 非 VMP |
| **企业版** | DEX 加密 + SO 加密 + RASP | 多 so 组合 + 反调试体 |
| **企业版 VMP** | 上面 + Native 代码虚拟化 | **`libffi` 命中** / 自研字节码 VM / 多 so 联动 |
| **私有化部署** | 全套 + 定制 | 各家不同 |

**判定口诀**：
```
libjiagu.so 单飞                  → 可能只是免费版（DEX 抽壳，成本低）
libjiagu.so + ffi_* 导入           → VMP 档
libjiagu.so + DynCryptor + 二次 so → 企业 VMP 全套
```

**实战结论**：本项目打到的都是**高档位** —— 爱加密 VMP（x64/ARM 两变体）、梆梆**企业版** VMP、网易易盾 VMP、腾讯 TP 自用全家桶。**不是免费版样本**。

**厂商性质区分**：
- **第三方商业加固**（公开卖）：爱加密、梆梆、网易易盾、360加固保、娜迦、几维…
- **大厂自研/半输出**（买不到或另开产品线）：**腾讯 TP（游戏自用）/ ACE（对外卖）**、阿里聚安全、**快手自研**

## 一·补、客户端安全 SDK / 反作弊（**非壳**，不要误判）

**「看到保护 so」≠「有壳」。** 这三层要分清：

```
第一层 · 加固壳        管 dex/so 能否被解出来       → 爱加密/梆梆/易盾VMP/360
第二层 · 安全 SDK      管设备/环境可不可信           → 腾讯图灵盾 / 快手自研 / 阿里聚安全
第三层 · 游戏反作弊    管有没有作弊（可到内核）      → 腾讯TP·ACE / 网易易盾 / 完美OneGuard
```

> ⚠ **易盾同时跨一、三层**：`libunisec.so`=加固（第一层，脱壳问题），`libsecsdk.so`=反作弊 VMP（第三层，反检测问题）。
> **腾讯同理分产品线**：加固是「乐固」那条线；**TP / ACE 是反作弊，不加壳**（证据：异环 5 dex 全明文却有 `libtprt`）。

| 组件 | 关键 so | 厂商 | 干什么 | 保护方式 |
|---|---|---|---|---|
| **图灵盾 turingd** | `libturingqps.so` | 腾讯 | **设备风控/设备指纹**（采集 OS/硬件/传感器/文件） | OLLVM |
| **图灵盾 turingmfa** | `libturingmfa.so` + `turingcam` | 腾讯 | **人脸防攻击** | OLLVM |
| **腾讯 ACE (TPrt/TSS)** | **`libtprt.so`** + `AceManager`/`AceDfgaApi` | 腾讯 | **游戏反作弊**（命令通道 `ioctl/gp6/gp7ioctl`；上报 `h.trace.qq.com/kv`） | **控制流平坦化 + 自有 raw svc 引擎 `tp_syscall_imp`** |
| **ACE 内核态 (PC)** | `ACE-BASE.sys` / `ACE-GAME.sys` | 腾讯 | PC 反作弊，**Ring-0** | 内核驱动 |
| **网易易盾** | `libsecsdk.so` | 网易 | 反作弊，**DEX-VMP** | `mutivmp` C 解释器解释 DEX 字节码 |
| **完美世界 OneGuard** | `com.wpsdk.onegameguard` | 完美世界 | 反作弊 | 上报 `clientlog.wanmei.com` |
| **完美世界 DFGA** | `libDfga_Catch.so` + `com.wpsdk.dfga` | 完美世界 | 设备指纹/崩溃捕获 | — |
| **阿里聚安全 SecurityGuard** | `libsgmain.so`（本质是 APK，真 elf 是 `libsgmainso-$VER.so`） | 阿里 | 白盒加密 + 安全签名（x-sign） | OLLVM + VMP + SMC |
| **快手自研** | `libkwsgmain.so`(205 裸 svc) + `libksse.so` + `libplt-*` | 快手 | RASP + 设备指纹（egid/gdfp） | 自研，检测器 `kssecurity::` 全在 native |

**多厂商叠加是常态**：异环 = **腾讯(ACE+图灵盾) + 完美世界(OneGuard+DFGA) + 网易(易盾VMP)** 四家同时上（异环/reports/78）。

**判据（一眼分辨三层）**：
| 看到这个 | 属于 | 结论 |
|---|---|---|
| dex 是空壳 / `libjiagu`·`mogosec`·`libDexHelper` | 第一层 壳 | **有壳**，要脱 |
| dex **原样明文** + `libkwsgmain`/`libturing*` | 第二层 SDK | **无壳**，别白费力气脱壳 |
| `libtprt`/`libsecsdk`/`libtersafe` | 第三层 反作弊 | 反检测问题，不是脱壳问题 |

**铁律**：**先判 dex 是不是明文**（一条命令），再谈有没有壳。异环和快手都是「5/30 个 dex 全明文」→ **直接排除壳**，省掉整条脱壳链。

## 二、逐壳详解

### 2.1 爱加密 Ijiami（本次主战 · 两个变体）

**厂商底色**：成都/深圳商业加固，`com.stub.StubApp` 桩 Application + `libjiagu*.so` / `libDexHelper*.so`。

#### 变体 A：VMP · x86_64 原生（`libjiagu_x64.so` / `libjiagu_64.so`）

| 维度 | 值 |
|---|---|
| 样本 | 掌上北工商 `com.lantu.MobileCampus.btbu` v3.0.0（Cordova+AngularJS）|
| 壳文件 | `assets/libjiagu{,_a64,_x64,_x86}.so` → 运行时释放到 `/data/data/<pkg>/.jiagu/` |
| SONAME | `libjiagu.so` |
| ELF | **x86-64 `ET_DYN`**，section header **伪造**（全叫 `..dynamic`，lief 打不开）|
| 大小 | 859,768 B（= `assets/libjiagu_x64.so`，MD5 `17d85f7b…`）|
| 导出 | `JNI_OnLoad`、`__arm_a_0/1/2`、`interpreter_wrap_{int64_t,float,double}[_bridge]`、`ffi_*` |
| 内置 | 完整 **libffi** + **zlib(inflate)** + 类 `DynCryptor` |
| 环境变量 | `JIAGU_APP_NAME/SO_BASE_NAME/ENCRYPTED_DEX_NAME/HASH_FILE_NAME/FILE_PATH`（`setenv` 自设）|
| 密钥来源 | `RMUTGF_KEY`（JNI `System.getProperty`）|
| 二次 so | `libijmDataEncryption` / `libjiagu_vip` |
| 反调试串 | `TracerPid`、`/proc/%d/{cmdline,pagemap,task/%d/mem}`、`_ZN3art3Dbg15gDebuggerActiveE`、`_Z25dvmDbgIsDebuggerConnectedv`、`rtld_db_dlactivity` |
| 反调试体 | `sub_8500`：inotify+select 阻塞 → SDK≤28 则 `kill(getpid(),9)`；`sub_3270/5ef0` 扫 `/proc/self/maps` |
| 自混淆 | 字符串 XOR 0xA5（`sub_7FA0`）；改造 RC4（`sub_74E0`：`i+=2; j+=S[i]+1`）|
| 壳线程 | `jg_ic_pool_thre` / `jg_timer` / `jg_mj_pool_thre` |
| 架构定位 | `0x79e3...` 原生区（**非** Houdini 转译）→ frida 可直接 hook |

**三连破**（详见本目录《爱加密VMP_x64_静态到动态破壳实战_2026-10-03.md》）：
1. 静态：lief 手解 PH + 84 导入解名 + IDA9.4 headless 批量反编译 + XOR-0xA5 解反调试串
2. 离线：unicorn + Qiling 补环境（重定位/TLS/导入桩）→ init_array 跑通 + 原语双引擎验证
3. 动态：**冷启动 attach 抢 0.53s 窗口** → 抓 `vm_parse_17410 / vm_11860 / libffi_187a0 / inflate_2e20 / mmap` 全链 → 71 个 dex（最大 9.2MB/6594 类）

**定性**：DEX 抽壳 + Native 代码虚拟化（自研字节码 VM + libffi）+ 二次 so 加密（DynCryptor）+ RASP 反调试 = **第三代 VMP 壳**。

#### 变体 B：VMP · ARM `libDexHelper`（+ x86 原生 `-x86`）

| 维度 | 值 |
|---|---|
| 样本 | 银行供应链金融 `com.yaodu.supplychain` |
| 壳文件 | `lib/arm64-v8a/libDexHelper.so`(ARM64) + `lib/arm64-v8a/libDexHelper-x86.so`(x86_64) + `libdexjni.so`(1.8MB ARM64) |
| 数据 | `assets/*.dat` RC4 加密 |
| 解密引擎 | `libdexjni.so` 函数 `0x1184`(1543 条 ARM64)，**RC4 变体**，密钥 `0x13068`(16B) |
| 反调试 | `/proc/PID/status`、`/proc/PID/maps`、`ptrace(PTRACE_TRACEME)`（**不查 `/proc/PID/mem`**）|
| 突破 | `setenforce 0` → Python 算 skip（避免 mksh 32 位截断）→ `dd if=/proc/PID/mem` 匿名 RW- 区拉 dex |

**与 A 的差异**：A 是"壳自身 VM + 冷启动抢窗口"，B 是"壳本体小 + 内存不锁 → 纯取证式 dd"。

#### 变体 C：`libgecko_encrypt.so`（红果短剧）

18KB so，`.text@0xa10`，内嵌 AES-256 key 字符串（44 字符 base64）；签名 `x-ss-stub = MD5(request body raw bytes).upper()`（295/295 复现）。属"轻量加密 so"，非完整 VMP。

### 2.3 网易易盾 / XT 盾（NetHTProtect）

| 维度 | 值 |
|---|---|
| 样本①手游 | 猫和老鼠 `com.netease.tom` v7.49.2；反作弊 `libunisec`(易盾系, arm64 + ntp x86_64) |
| 样本②Unity | ATM Legend `com.joym.atmlegend2.yofun`（IL2CPP + NetHTProtect）|
| 核心漏洞 | XT 加密磁盘 `global-metadata.dat`，但**运行时必须解密进内存** → 内存里有明文 |
| 突破（通杀）| ① `cat /proc/PID/maps | grep global-metadata` 找 `rw-p` 映射 → ② dump 内存 → ③ 去 336B XT 自定义头（搜 `0xFAB11BAF`）→ ④ Il2CppDumper |

| 风险 | 行为上报（unisec 文件 66746 次/60s）→ 延迟封号 |

## 四、按"保护类型"选打法

| 保护类型 | 代表 | 首选打法 | 为什么 |
|---|---|---|---|
| **DEX 抽壳**（真 dex 只在内存）| 爱加密、梆梆 | 运行时 dump（frida-dexdump / 冷启动扫内存 / dd /proc/mem）| 磁盘无密文，只能运行时 |
| **Native VMP**（壳自身 VM）| 爱加密 VMP、梆梆 VMP | 别硬逆 VM；冷启动 hook 抓「解密→加载」链，或直接 dump 解密后 dex | 逆 VM 语义成本极高 |
| **内存不锁型**（解密后裸放匿名区）| 爱加密 libDexHelper | `setenforce 0` + `dd /proc/PID/mem` | 壳不检查 /proc/mem |
| **完整性校验型**（改代码就死）| 腾讯 TP | 时序窗口法（≤12s）+ 最小 hook | 周期扫描、事件驱动 |
| **环境交叉校验型**（伪造就崩）| 网易易盾 | 保持环境原值（勿伪造 cpuinfo）| 启动期 ARM 视图 vs 真值比对 |
| **引擎级**（Unity/UE）| 易盾 metadata、UE IoStore | 内存 dump 去头 / retoc | 引擎必须解密才能跑 |
| **脚本级 VM** | 猫和老鼠 Lua | 内存抓密钥管线 | 密钥运行时构造 |

## 五、铁律（踩过的坑，跨壳通用）

1. **观测永远安全，修改才有风险** —— strace/eBPF/attach 不触发检测，inline hook 才触发（TP/易盾实测）。
2. **冷启动是抢启动期的唯一窗口** —— 热 attach 时 `JNI_OnLoad`/解密早跑完；模拟器 **spawn 会崩**（houdini），只能 `am start` + 立即 attach。
3. **先看 maps 判原生/转译** —— `0x7xxx`=原生可直接 hook；`0x4000xxxx`=转译（frida 模块表看不到，但按 base 仍可 attach）。
4. **进程枚举可能漏主进程** —— 用 `pidof` 拿 PID 硬 attach，别信 `enumerate_processes`。
5. **伪装有风险，先确认交叉校验** —— 不确定就用 `strace -P` 看运行期读不读该文件（读=可伪造；不读=启动校验=勿动）。
6. **死码地址特征** —— `0xdeadXXXX`（如 `0xdead1001`）= 检测自杀，不是随机崩溃。
7. **libc 归属法** —— hook 全局 libc 函数时用 `Process.findModuleByAddress(this.returnAddress)` 判调用方，否则会把 WebView/Chrome 的调用误判成壳。
8. **frida server 连一次就断** —— attach 前 `killall nsv11` 重启；端口 31337。
9. **mksh 的 `$(( ))` 32 位截断** —— `dd skip` 必须 Python 算十进制，别在 shell 里算。
10. **脱壳非破坏** —— dump 的是内存里已解密的 bytecode，不改壳算法、不碰业务，属运行时绕过。
