# 爱加密（Ijiami）VMP 实战 — x86_64 原生 `libjiagu_64.so`（静态→离线→动态三连破）

> 2026-10-03 实战验证 | 目标: 掌上北工商 `com.lantu.MobileCampus.btbu` v3.0.0
> 环境: MuMu / Android 15 / x86_64 **无 Houdini**（壳是原生 x86_64，直接可 hook）
> 姊妹篇: 同目录《爱加密VMP模拟器运行时绕过_2026-09-14.md》（那篇是 ARM `libDexHelper` 变体 + 纯内存取证）

## 一、一句话

爱加密 VMP 在 **x86_64 原生**形态下（`libjiagu_64.so`/`libjiagu_x64.so`）**既能静推定身份、又能离线跑原语、还能冷启动 hook 抢窗口 dump dex**——三连全通。关键突破点是**冷启动 attach 抢 0.5 秒窗口**（不是 spawn，模拟器 spawn 会崩）。

|---|---|---|

| 解密密钥 key | `RMUTGF_KEY` | 走 JNI `System.getProperty("RMUTGF_KEY")` |

```

```

## 四、① 静态定性（先看壳的"能力面"）

### 4.1 认 ELF 真身

```python
# lief 打不开 → 说明 section header 被伪造，改手解
import struct
d = open(so,'rb').read()
e_machine = struct.unpack_from('<H', d, 18)[0]     # 0x3e = x86-64
```
> 这个壳的 `e_shstrndx` 段表**全叫 `..dynamic`**（伪造）→ lief 报 `Failed to open`，必须手解 program header。

### 4.2 解导入表（子函数 → 真实 API）

`sub_2D20..sub_3260` 是 84 个 16B PLT thunk（`jmp qword [rip+disp]` → GOT）。手扫 `ff 25 xx xx xx xx` + 解 `.rela.plt` 符号名：

```python
# 关键发现：壳的真实能力 = 反调试 + 内存加载 + 解压
#  kill  prctl  inotify_init/add_watch  select  __FD_SET_chk   ← 反调试循环
#  dl_iterate_phdr  dladdr  dlsym  mprotect  __clear_cache     ← 内存建 ELF / 自改码
#  inflateInit_  inflate  inflateEnd                            ← 解密 dex 后再解压
#  ffi_prep_cif  ffi_call  ffi_closure_unix64_inner  ffi_type_* ← 自研解释器骨架
```

### 4.3 反调试字符串（XOR 0xA5 解出）

壳内 `sub_7FA0` 就是 XOR-0xA5 块解密器（`xmmword_1C390` = 全 `0xA5`）。解出的明文串：

| 明文 | 用途 |
|---|---|
| `/proc/self/status` + `TracerPid` | ptrace 检测 |
| `/system/bin/linker` + `rtld_db_dlactivity` | 读 linker 断点变量 |
| `_ZN3art3Dbg15gDebuggerActiveE` / `_ZN3artL15gDebuggerActiveE` + `/system/lib/libart.so` | ART 调试器符号 |
| `_Z25dvmDbgIsDebuggerConnectedv` + `/system/lib/libdvm.so` | Dalvik 调试器检测 |
| `/proc/%d/cmdline` `/proc/%d/pagemap` `/proc/%d/task/%d/mem` | 进程/页表/跨线程内存 |

### 4.4 反调试执行体（`sub_8500`）

`getpid()` → `inotify_init` + `inotify_add_watch(...,4095)` → `select(1024,...)` 阻塞 → `read` 事件 → 若 SDK `<=28` 则 **`kill(getpid(), 9)`**。主线程 `prctl` 改名 + `pthread_create/detach` 起看守线程。

> 实测线程名：`jg_ic_pool_thre` / `jg_timer` / `jg_mj_pool_thre`（`jg_`=jiagu），`jg_timer` 阻塞在 `do_epoll_wait`。

### 4.5 用 IDA 9.4 headless 批量反编译

```bash
"D:\IDA Pro 9.4.260714\idat.exe" -A -S"script.py OUT_DIR" target.so
```
脚本内 `ida_auto.auto_wait()` → `ida_hexrays.decompile(ea)` → `idc.qexit(0)`。
**未重定位的 .so 直接用文件 vaddr**，别加 imagebase（9.4 无 `get_imagebase`）。

## 五、② 离线执行（补环境两大件）

壳是「Java 壳」——全部逻辑走 `JNIEnv` 虚表 + 自研解释器，**离线要能跑就得补 JNIEnv；仅验证叶子算法则不必**。

### 5.1 补环境清单（实测）

| 项 | 不补后果 | 补法 |
|---|---|---|
| **重定位** | GOT 空 → `call [GOT]` 跳 0 | 手扫 `.rela.dyn/.rela.plt`：`R_X86_64_RELATIVE(8)` → `base+addend`；`GLOB(6)/JUMP(7)/64(1)` → 符号地址或导入桩 |
| **TLS 金丝雀** | `mov rax, fs:[0x28]` 崩 | 这个 so **无 PT_TLS** → 自建 TLS 块，`fs:+0x28` 放 canary，`fsbase` 指过去 |
| **导入语义** | 桩全裸 `ret` → 返回值垃圾 → 写野地址 | `_Znwm/_Znam/malloc/calloc` 用 bump 分配器；`strlen/strstr/strcpy/memcpy/atoi` 按语义实现 |
| **`dl_iterate_phdr`** | 返回 0 使壳判无模块 | 回调喂一个 `dl_phdr_info{addr,name,phdr,phnum}` |

### 5.2 验证（双引擎一致才算过）

```
[1] init_array[0] @0xc670 -> 返回哨兵 OK（34254 指令，unicorn & Qiling 都过）
[2] sub_7FA0 XOR-0xA5 : OK   in 0001020304050607 -> out a5a4a7a6a1a0a3a2
[3] sub_74E0 改造RC4  : OK   keystream 050c15182938495c716891acc9e80910
```

> `sub_74E0` 是**改造 RC4**（PRGA 改成 `i+=2; j+=S[i]+1`）——不是标准 RC4，别用现成库对。

### 5.3 Qiling 特有的坑

- 必须用**源码版**（`pip` 的是空壳）：`sys.path.insert(0, r"D:\逆向工具\qiling\qiling-master")`
- Qiling 自带加载器**不解析这个 so 的导入**（段表伪造）→ GOT 留垃圾 → 必须自己填 GOT 桩
- **跑初始化链仍需假 JNIEnv**；只跑叶子函数则上面四件够

### 5.4 判据：什么时候纯离线就够 / 什么时候必须动态

| 目标 | 纯离线 | 原因 |
|---|---|---|
| 壳身份/算法/反调试分析 | ✅ | 纯静态 |
| 跑壳内部原语 | ✅ | 喂 buffer |
| **提取真 dex** | ❌ **必须动态** | 真 dex 只解密到内存匿名区，磁盘/APK 无密文副本 |

## 六、③ 动态破壳（冷启动抢窗口 + dex dump）★核心

### 6.1 为什么必须冷启动

热进程里 `JNI_OnLoad`/解释器/解密**早在启动时就跑完了**，attach 上去 hook 这些点全 0 命中（不是 hook 失败，是没东西可抓）。
→ **唯一窗口是冷启动那 0.5 秒**。

### 6.2 frida 环境（MuMu + nsv11）

```powershell
$ADB = "D:\MuMuPlayer\nx_main\adb.exe"
& $ADB -s 127.0.0.1:7555 shell su -c "killall nsv11 nosuke-server-v3"   # 清旧 server（连一次就断的坑）
& $ADB -s 127.0.0.1:7555 shell su -c "chmod 755 /data/local/tmp/nsv11"
# 用 run_background 起 server（不要 nohup &）
& $ADB -s 127.0.0.1:7555 shell su -c /data/local/tmp/nsv11
& $ADB -s 127.0.0.1:7555 forward tcp:31337 tcp:31337
```
> 端口是 **31337**（不是 27042/8080）。API 是 nosuke 改名版：`getModuleByName` / `findGlobalExportByName`。

### 6.3 抢窗口的写法（关键）

```python
# 别用进程枚举（模拟器枚举漏主进程），也别用 spawn（houdini 会崩）
adb("shell","am","start","-n","pkg/.MainActivity")     # 起 app
t0=time.time()
while time.time()-t0 < 20:                              # 30ms 一轮暴抢
    pid = adb("shell","pidof", pkg).strip().split()[0]  # 直接拿主进程 PID
    try:
        sess = dev.attach(int(pid)); sc = sess.create_script(JS); sc.load()
        print("attach OK after %.2fs" % (time.time()-t0)); break
    except Exception: time.sleep(0.03)
```
实测 **0.53s** 挂上。

**JS 侧**：`setInterval(armOnce, 5)` 轮询 `Process.findModuleByName('libjiagu_64.so')`，模块一出现立刻 `Interceptor.attach`（用**文件 vaddr** 当 RVA，因为壳没 ASLR-重定位偏移）。

### 6.4 dex 扫描 + dump（判据驱动）

```javascript
['r--','rw-','r-x'].forEach(perm =>
  Process.enumerateRanges(perm).forEach(r =>
    Memory.scanSync(r.base, r.size, '64 65 78 0a 30 33').forEach(h => {  // "dex\n03"
      var u = new Uint8Array(h.address.readByteArray(0x70));
      if (u[4]!==0x30 || u[7]!==0) return;                 // dex\n0XX\0
      var fs = u32(u,32), hs = u32(u,36);                   // file_size / header_size
      if (fs<0x70 || fs>0x4000000 || hs!==0x70) return;     // 过滤
      send({kind:'dex', name}, h.address.readByteArray(fs));// 按 file_size 精确 dump
    })));
```

### 6.5 冷启动实测抓到的调用链（定性被验证）

| 命中 | 次数 | 对应 |
|---|---|---|
| `open/fopen` | 3+9 | 打开加密资源 |
| `vm_parse_17410` | 4 | VM 字节码解析器 |
| `vm_11860` | 4 | VM 执行器 |
| `libffi_187a0` | 121+ | 解释器经 libffi 调 sink |
| `inflate_2e20` | 96 | zlib 解压解密后的 dex |
| `mmap_2db0` | 16 | 匿名内存放 dex |
| `pthread_3080` | 3 | 起 jg_* 看守线程 |

→ **"自研 VM + libffi + zlib"** 从猜测定性变成真机实证。

## 七、常见坑（本变体实测）

| 坑 | 现象 | 解法 |
|---|---|---|
| frida `connection closed` | 连一次就断 | `killall nsv11` 重启 server |
| 进程枚举漏主进程 | `enumerate_processes` 只见 `:pushcore` | 用 `pidof` 拿 PID 硬 attach |
| 重脚本 `load()` 超时 | `TransportError: timeout` | 扫描放 `setTimeout`，别在 load 同步跑 |
| spawn 崩 | `-f` 起不来 | 绝不用 spawn，改冷启动 attach |
| 热 attach hook 全 0 | 抓不到 JNI/解密 | 冷启动抢窗口 |
| lief 打不开 | section header 伪造 | 手解 program header |
| `jmp [GOT]` 跳 0 | 离线跑飞 | 手动填 GOT + 重定位 |
| 认成转译 | 乱 hook houdini | **看 maps 地址区**：`0x7xxx` 原生 / `0x4000xxxx` 转译 |

## 八、定性结论

> **爱加密 VMP 版 = DEX 抽壳 + Native 代码虚拟化（自研字节码 VM + libffi）+ 二次 so 加密（DynCryptor）+ RASP 反调试**

| 层 | 类型 | 实证 |
|---|---|---|
| 壳本体 | DEX 加密壳（运行时解密） | 真 dex 只在内存匿名区 |
| 保护强度 | VMP（第三代） | 壳自身 `JNI_OnLoad` 即 VM 字节码；libffi 命中 121+ |
| 二次加密 | 共享库加密 | `JIAGU_ENCRYPTED_DEX_NAME` + `DynCryptor` |
| 自保护 | RASP | TracerPid/proc 监控/inotify→kill/自改码 |

**架构定位**：x86_64 **原生**（`0x79e3...` 区，非 Houdini 转译）→ 可直接 frida hook。

**业务与壳解耦**：本样本是 Cordova + AngularJS（H5 混合），业务逻辑在**明文 JS** 里，壳只保护 dex 加载与反调试 → 前端接口/签名纯静态可逆，dex 必须动态 dump。
