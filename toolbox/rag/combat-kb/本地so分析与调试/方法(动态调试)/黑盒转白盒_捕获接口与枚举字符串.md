# 方法(动态调试)：黑盒转白盒 —— 捕获接口 · 枚举字符串 · 直接调函数

> 定位：库**静态读不动**（混淆/VMP/串混淆）时，用 unidbg/Qiling **在本地把"接口·字符串·函数"抠出来**。
> 判据驱动，**不举具体实例**；只讲"什么信号 → 怎么做 → 拿到什么"。

---

## 一、判据总表：什么信号，用什么招
| 信号 | 招式 | 拿到 |
| --- | --- | --- |
| 库导出少、逻辑在 `JNI_OnLoad`/`init_array` | 跑 init，看它调什么 | 初始化行为/依赖 |
| Java 侧 native 方法不明 | **hook `RegisterNatives`** | 全部 native 方法名+签名+fnPtr |
| 串"加密/乱码" | 找**取串函数**并枚举 | 完整字符串表 |
| 有"分发/协议"函数 | `callFunction` 逐个喂参数 | 命令语义/协议格式 |
| 库"早崩/卡住" | **auto-map 未映射页** + 补 JNI | 让 init 跑到底 |
| 想知道"哪层读环境" | 分层判据（见§五） | hook 落点 |

---

## 二、★捕获接口：hook `RegisterNatives`
库在 `JNI_OnLoad` 里用 `env->RegisterNatives(clazz, methods[], n)` 注册 native 方法。
- `RegisterNatives` 是 **JNIEnv 函数表第 215 项**。
- 做法：造假 JNIEnv（函数表全指向 `ret` 桩），把**第 215 槽**指向自己的桩 → 读参 `(env,clazz,methods,n)`。
- `JNINativeMethod = { const char* name; const char* sig; void* fnPtr; }`（24B/项）。
- **产出**：全部 native 方法名+签名+**fnPtr(运行时地址=base+offset)** → 后续逐个 `callFunction` 跑。

```java
// 伪: 第 215 槽 -> 桩, 桩里读 methods+i*24 的 name/sig/fnPtr
```

## 三、★枚举字符串：找"取串函数"再枚举 id
**判据**：反编译里出现 `xxx(id)` → `array[id % N]()` 这种"**按 id 取串**"的模式 = **N 个取串函数的串混淆**（不是真加密）。
- 用反编译(IDA)拿到取串函数偏移与 `id%N` 的 N。
- **直接 `callFunction(取串函数, id)`** 枚举 id（0..数千），读返回的 C 串 → **dump 全字符串表**。
- **产出**：库的全部明文串（检测路径/协议/命令名…）→ **黑盒变白盒**。

```java
for(long id=0; id<N_upper; id++){
    Number r = module.callFunction(emulator, <取串函数offset>, id);
    System.out.println("["+id+"] '"+readCStr(r.longValue())+"'");
}
```

## 四、直接调任意函数：`Module.callFunction`
- **签名**：`Number callFunction(Emulator<?,?> emulator, long offset, Object... args)`（`offset` **相对模块基址**；返回值是 `Number`，**不是数组**）。
- 用途：喂参数调"分发/协议/取串/加解密"函数，看输入→输出。
- **坑**：返回 `Number`（若当 `Number[]` 用会编译错）；`offset` 是相对 base。

---

## 五、★分层判据：谁跑在哪层 → 就在哪层 hook
> 核心：**看它"读环境"走哪条路**，就在那条路堵。

| 读环境方式 | 所在层 | hook 落点 | 工具 |
| --- | --- | --- | --- |
| Java API（`getPackageName`/`Settings.Secure`）| Java | 改方法返回 | Frida `Java.use` |
| **libc 函数**（`open`/`prctl`/`popen`）| libc | `Interceptor.attach(libc导出)` | Frida |
| **libc `syscall()` 包装器** | libc | hook `syscall` | Frida |
| **内联 `svc #0`** | raw svc | **libc 钩不到** → patch svc / seccomp | `frida_svc_patch` / Stalker |
| **自带 syscall 引擎**（如 `xxx_syscall(nr,...)`）| raw svc | **hook 那个引擎** | Frida |
| **100 取串函数 / VMP** | 代码级 | 反编译 + 枚举 | IDA + unidbg |

**判据**：`objdump`/脚本扫 `.text` 数**内联 `svc` 条数**（0=全 libc；>0=有绕过）；看是否有**自定义 syscall 引擎导出**。

## 六、让库"跑到底"：auto-map 未映射页
- 库 init 常因缺环境**早崩**（`UC_ERR_FETCH/WRITE_UNMAPPED`）。
- **Qiling**：`ql.uc.hook_add(UC_HOOK_MEM_UNMAPPED, cb)`，cb 里 `mem_map(addr&~0xfff,0x1000)` 返回 True → 继续跑。
- 效果：`JNI_OnLoad` 从"早崩"到"**跑到底**"，从而触发到真正的行为（如读文件、进 syscall 引擎）。

---

## 七、Qiling vs unidbg 选型（互补）
| | Qiling | unidbg |
| --- | --- | --- |
| 层 | 纯原生 | 原生 + 真 Dalvik/JNI |
| 强项 | 干净 hook / 追 syscall | **真 JNIEnv**：能调 native 方法、返回 Java 对象 |
| 用途 | 看"读环境行为"（文件/syscall）| **枚举字符串、跑接口、触发自退** |
| 局限 | JNIEnv 全 stub | hook 地址/API 要试 |

**组合拳**：Qiling 看**行为**（读了哪些 `/proc`），unidbg 做**提取**（枚举串、调函数）。

---

## 八、产物闭环
```
RegisterNatives → 接口清单(native 方法)
取串函数枚举   → 字符串表(检测路径/命令/协议)
callFunction   → 命令语义/协议格式/加解密 I/O
分层判据       → hook 落点(Java/libc/svc/引擎)
```
→ 这套下来，**黑盒变白盒**；再据此写 Frida 或补环境。
