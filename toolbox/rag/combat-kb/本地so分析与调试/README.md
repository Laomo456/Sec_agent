# 本地 SO 分析知识库

> 定位：不依赖真机/模拟器，把 Android `.so` 拉回 Windows 本地做 **静态分析 + 动态执行（unidbg / Qiling）**。
> 环境：Python 3 + capstone | JDK + unidbg | Qiling（源码版）| IDA Pro
> 本库只讲"**测什么 / 怎么测 / 产出什么**"，判据驱动，**不举具体实例**。

## 核心原则

1. **静态先行**：`readelf` / `strings` / 反汇编能定结构信息，别一上来就跑。
2. **导出与接缝 = 逻辑面清单**：先把入口（JNI / 导出 / 注册表）列全，再逐个攻。
3. **材料不在代码里就别硬逆算法**：先定位运行时来源（资源 / 文件 / 网络 / 派生），再决定喂数据 or 抄参数。
4. **hook 最小化**：只顶掉必须顶的（资源管理器 / 文件读取等），其余让库自己跑，减少行为偏差。
5. **闭环验证**：**变换 A 的结果能被逆向变换 B 还原** = 环境 / 参数补对了，这是"模拟可信"的硬标准。
6. **先定目标再动手**：先问"为什么 / 要测什么"，再定"怎么测"，最后执行。

## 工作流总览

```
拿到 .so
  │
  ├─ 1. 明确目标（目的/目的.md §1-2：要测的六件事）
  │
  ├─ 2. 静态定面（方法/方法.md）
  │     ├─ file / readelf -h/-S/-l/-d/-r（架构 / 壳 / 布局）
  │     ├─ readelf --dyn-syms + strings（接缝 / 特征字符串）
  │     └─ capstone / IDA 反汇编（init_array / JNI_OnLoad / 目标函数）
  │
  ├─ 3. [需跑] 本地动态执行（选一）
  │     ├─ unidbg（方法(动态调试)/unidbg本地hook.md）
  │     │     └─ 带 JNI / Java 回调的场景首选
  │     └─ Qiling（方法(动态调试)/Qiling本地执行.md）
  │           └─ 自包含算法 / 无 JNI / 需补重定位的环境
  │
  ├─ 4. [需真机] 设备端动态 hook（配套 Frida 手册）
  │
  └─ 5. 产出（目的/目的.md §6）
        锚点清单 / 材料 / 明文 / 绕过 / 依赖清单
```

**选型速记**：

| 场景 | 首选 |
| --- | --- |
| 纯算法（白盒 / 自实现加密）| Qiling（补环境后跑） |
| 带 JNI + Java 回调 | unidbg（MyJni 演 Java） |
| 需要真实网络 / 系统调用 | 真机 Frida |
| 反复调参、秒级重试 | unidbg / Qiling 本地 |
