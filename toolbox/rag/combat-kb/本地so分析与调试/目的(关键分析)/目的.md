# 目的：SO 分析要测什么

> 定位：为什么分析 SO、**要测什么**、产出什么、怎么判定"测到了"。
> 核心原则：分析 SO 不是为了"看明白"，而是为了**产出可操作的锚点与数据流模型**，直接支撑动态调试 / 抓包 / 协议还原。
> 本文件只讲"测什么、怎么判定"，**不举具体实例**。

---

## 1. 总目的：把不透明库转成"可操作模型"

分析 SO 的终点不是一份反汇编，而是三样可操作的东西：

| 产出形态 | 含义 | 下游用途 |
| --- | --- | --- |
| **能挂** | 一组稳定的 hook 锚点 | attach 不崩、能抄参数 |
| **能喂** | 外部依赖 / 环境清单 | 模拟执行时喂对数据 |
| **能解释** | 数据流与变换模型 | 知道明文在哪、怎么变换 |

**判定"分析到位"的唯一标准**：能回答第 2 节的六个问题。

---

## 2. 要测的六件事（目的的具体化）

| # | 要测的问题 | 判定标准（测到什么算完成） |
| --- | --- | --- |
| 1 | **数据流边界**：明文 / 密文 / 签名分别在哪一层产生与消费 | 能画出"业务数据 → 变换 → 传输"的层间边界 |
| 2 | **数据变换**：每个边界做的是什么变换 | 每层能指出算法**类别** + 参数面（key / iv / nonce / 计数器 / 域） |
| 3 | **密钥与材料来源**：key 从哪来 | 判定为 静态硬编码 / 运行时派生 / 白盒查表 / 服务器下发 之一 |
| 4 | **入口与接缝**：稳定的 hook 锚点在哪 | 列出 JNI / 导出 / 注册表 / 回调 清单 |
| 5 | **防护**：有哪些检测、何时触发 | 每类检测能定位函数 + 判定 一次性 / 持续 |
| 6 | **运行时依赖**：跑起来依赖什么 | 列出外部 API、设备指纹、资源 / 文件路径 |

### 为什么是这六件事，而不是"看懂算法"

- 目标决定深度：要的是**"挂得上、喂得进、解得开"**，不是"看懂混淆后的算法"。
- 六件事都**可判定**（有明确完成信号），避免陷入无底洞反编译。
- 六件事直接对应下游动作：hook / 模拟 / 解密 / 伪造。

---

## 3. 关键分析点（怎么测这六件事）

### 3.1 入口与接缝（优先，最稳的 hook 锚点）

| 步骤 | 做什么 | 判据 |
| --- | --- | --- |
| 1 | 找 `JNI_OnLoad` / `RegisterNatives` | 确认存在 JNI 注册 |
| 2 | 列导出符号（`grep Java_` / dyn-syms） | 得到接口清单 |
| 3 | 反汇编注册表 | 得到 `{name, sig, fnPtr}` → name→fn 映射 |

- **JNI 命名规则**：`Java_包名_类名_方法名`；转义 `_1` = `_`，`_2` = `;`，`_3` = `[`。
- 除 JNI 外，**其它稳定接缝**同样算锚点：导出 C 函数、虚表回调、注册的 listener、`dlsym` 名字。
- 判据：**能在不改数据流的前提下 attach 上去**（锚点越靠近接缝越稳）。

### 3.2 数据流边界与变换

| 组件 | 作用 | 找法 | 产出 |
| --- | --- | --- | --- |
| TLS 栈（OpenSSL / BoringSSL / 自研）| TLS 层读写 | `strings` 找 `SSL_` / `TLS_` / `X509_` | hook 拿 TLS 明文 |
| 应用层加密 | TLS 之上再套一层 | `strings` 找 `encrypt` / `decrypt` / 算法名 | hook 应用层明文 |
| 自定义协议打包 | 业务数据 → 协议 buffer | 反汇编找序列化 / 打包逻辑 | 协议格式 |
| HTTP 客户端 | 请求 / 响应 | `strings` 找 HTTP / 自研客户端 | hook 请求响应 |

- **要判定的关键问题**：网络是**纯 TLS**，还是 **TLS + 应用层加密**？
  - 纯 TLS → 解决 TLS 层即可见明文
  - 叠加应用层 → 必须再 hook 应用层变换函数
- 判据：能指出**每一层的输入/输出形态**（明文 / 密文 / 签名 / 编码）。

### 3.3 密钥与材料来源（最值钱）

| 类型 | 常见形式 | 找法 | 产出 |
| --- | --- | --- | --- |
| 硬编码对称密钥 | 固定长度字节数组 / 字符串 | `strings` + 反汇编找常量加载（`ldp`/`ldr`） | 可离线解密 |
| 非对称密钥 | PEM / DER | `strings` 找 `BEGIN ... PRIVATE KEY` | 可解密响应 / 伪造 |
| 派生材料 | 设备指纹 + 服务器 nonce | 反汇编找指纹 API 调用点 | 必须运行时取 |
| 证书固定材料 | 公钥 / 证书 hash | `strings` 找证书 / 公钥 hash / pin 串 | 可解固定 |
| 白盒密钥 | 查表实现的变换 | 反汇编找大段轮转查表 | 必须模拟 / hook |

- **关键判定**：key 是**静态**（硬编码）还是**动态**（运行时派生/下发）？
- **效率原则**：**材料"不在代码里"时不要硬逆算法** —— 先定位它运行时从哪读（资源 / 文件 / 网络），再决定喂数据 or 抄参数。
- 判据：能给出"材料从哪来 + 怎么拿到"的确定结论。

### 3.4 防护（反调试 / 反注入 / 反环境）

| 检测类型 | 常见手法 | 找法 | 绕过方向 |
| --- | --- | --- | --- |
| 调试器占坑 | 自跟踪 / 抢占 | `strings` 找 `ptrace` | replace 返回"未调试" |
| 内存图扫描 | 扫注入框架特征 | `strings` 找 `maps` / 框架名 | hook `open`/`read` 过滤 |
| 线程 / 端口检测 | 找注入线程 / 端口 | `strings` 找线程名 API / socket | hook 对应 API |
| 完整性校验 | 校验自身 hash / 内存 | `strings` 找 `sha256` / `md5` | hook 校验函数返回"通过" |
| 时间差检测 | 断点导致的时延 | 反汇编找时钟调用 | hook 时间函数 |
| 环境 / 模拟器检测 | CPU / 设备 / 指纹特征 | `strings` 找属性查询 API | hook 属性查询 |

- **关键判定**：检测是**启动一次性**还是**运行时持续**？
  - 一次性 → 过启动检测即可
  - 持续 → 必须 replace 检测函数一直返回"安全"
- 判据：**能定位到具体检测函数，并给出触发时机**。

### 3.5 运行时依赖

| 依赖类别 | 作用 | 找法 |
| --- | --- | --- |
| 外部 API（libc / 系统）| 执行环境 | 看导入表 / `bl` 到 PLT |
| 设备指纹 | 派生材料来源 | 反汇编找属性 / 标识 API |
| 资源 / 文件 | 密钥、配置、证书 | `strings` 找路径 / 资源名 + 加载逻辑 |
| 全局初始化（constructor）| 运行时前置状态 | `.init_array` / `.preinit_array` |

- 判据：能列出**"喂数据 / 补环境"最小清单**（缺什么会跑不下去）。

## 4. 静态 / 动态 / 模拟 的分工

| 问题 | 静态可答? | 动态可答? | 模拟可答? |
| --- | --- | --- | --- |
| 函数在哪、叫什么 | ✅ 符号 + 反汇编 | ✅ 运行时符号 | ✅ 加载即得 |
| 调了哪些外部 API | ✅ 看 `bl` + 导入表 | ✅ 调用日志 | ⚠ 需补环境 |
| 输入→输出的变换 | ❌ 白盒 / 加密必须跑 | ✅ hook 参数 | ✅ 喂数据跑通 |
| 密钥 / 盐值到底是什么 | ❌ 运行时才产生 | ✅ hook 抄参数 | ✅ 喂数据得到 |
| 检测在哪、查什么 | ✅ strings 找特征 | ✅ 看调用栈 | ⚠ 可能触发检测 |

**分工原则**：
- 静态定**面**（函数位置、接口、检测字符串、依赖清单）——约 80% 的"结构信息"。
- 动态 / 模拟定**值**（密钥、变换结果、运行时行为）——剩下的"运行信息"。
- **大体积 / 强混淆的库不做静态全反编译**，改由运行时观察它调了什么。

---

## 5. 什么时候该停

| 完成信号 | 含义 |
| --- | --- |
| **接缝清单已列出** | 知道 hook 哪些点，可转动态 |
| **材料来源已确认** | 静态 / 派生 / 白盒 / 下发 已判定 |
| **检测已定位** | 知道查什么、何时触发，可绕过 |
| **数据流边界已确认** | 知道明文在哪一层 |

**不要**：
- 把整个 SO 反编译完（强混淆下看不懂，纯浪费）。
- 硬逆白盒算法（**定位材料来源比逆算法快一个量级**）。
- 对超大 / 强混淆库做静态全量（运行时观察更高效）。

## 6. 产出

| 产出 | 说明 | 用法 |
| --- | --- | --- |
| **锚点清单** | 接缝函数 / 注册表 / 回调 | 直接 hook |
| **材料** | 对称 / 非对称密钥、派生种子、pin 材料 | 离线解密 / 伪造 / unpin |
| **明文** | 各层变换前后的数据 | 抓包分析 / 协议还原 |
| **绕过** | 各类检测的处理方案 | 保证 attach / hook 稳定 |
| **依赖清单** | 外部 API / 指纹 / 资源 | 模拟执行补环境 |

**产出决策树**：

```
分析 SO
  │
  ├─ 材料来源？
  │   ├─ 静态 → 离线解密
  │   ├─ 动态 → hook 运行时抄
  │   └─ 白盒 → 模拟执行 / hook
  │
  ├─ 检测？
  │   ├─ 一次性 → 过启动
  │   └─ 持续   → replace 检测函数
  │
  ├─ 数据流边界？
  │   ├─ 纯 TLS → 处理 TLS 层
  │   └─ TLS + 应用层 → hook 应用层变换
  │
  └─ 接缝？
      ├─ 确定 hook 点
      └─ 确定伪造 / 重放入口
```

---

## 7. 核心原则

1. **静态先行**：能定结构信息（位置 / 接口 / 字符串）就别一上来跑。
2. **导出与接缝 = 逻辑面清单**：先把入口列全，再逐个攻。
3. **材料不在代码里就别硬逆算法**：定位运行时来源，喂数据 / 抄参数更快。
4. **hook 最小化**：只顶掉必须顶的，其余让库自己跑，减少行为偏差。
5. **闭环验证**：**变换 A 的结果能被逆向变换 B 还原** = 环境 / 参数补对了，这是"模拟可信"的硬标准。
6. **先定目标再动手**：先问"为什么 / 要测什么"，再定"怎么测"，最后执行。
