# 方法：SO 静态分析技术链

> 定位：不依赖真机/模拟器，用静态手段把 Android `.so` 分析"到位"。
> 判据驱动，**不举具体实例**。（本地动态执行见 `方法(动态调试)/`。）

---

## 1. 速查：拿到 SO 后 5 分钟确认

### 1.1 架构
```bash
file target.so
readelf -h target.so
```
- `ELFCLASS`：32 = armeabi-v7a，64 = arm64-v8a → 决定后续反汇编架构（capstone / IDA）。
- `e_machine`：`AArch64` = ARM64，`ARM` = ARM32。
- `.so` 的 `Entry point` 通常无意义，看向 `.init_array`。

### 1.2 节表 / 壳判断
```bash
readelf -S target.so
```
| 节名 | 作用 | 壳特征 |
| --- | --- | --- |
| `.text` | 代码 | 干净 so 必有 |
| `.dynsym` / `.dynstr` | 导出符号 | 被抹 = stripped + 壳 |
| `.init_array` | 启动函数表 | 壳解密 / 反调试 / 环境校验常藏 |
| `.data` / `.bss` | 全局 / 未初始化 | 密钥表 / 白盒表常藏 |
| `.rodata` | 字符串 / 常量 | `strings` 首选 |

壳信号：`.text` 段名改写、节名全删、高熵无反汇编、`init_array` 指向非 JNI 逻辑。

### 1.3 程序头 / 运行时布局
```bash
readelf -l target.so
```
- `LOAD R+X` = 代码段，`LOAD RW` = GOT / `.data` / `.bss`。
- **无偏移 so**：`p_offset == p_vaddr` 时，文件偏移 = 虚址，`data[vaddr:...]` 可直接反汇编。
- 否则：`file_off = vaddr - seg.vaddr + seg.offset`（务必先转换，别默认相等）。
- GOT 槽偏移查 `readelf -r`（重定位表）——**懒绑定槽**是动态绕过的关键。

### 1.4 动态符号 / 接缝（最重要）
```bash
readelf --dyn-syms target.so | grep Java_      # 通用导出
readelf --dyn-syms target.so                    # 全部导出
```
- JNI 命名：`Java_包名_类名_方法名`；转义 `_1`=`_`，`_2`=`;`，`_3`=`[`。
- 除 JNI 外，**导出 C 函数 / 导出表**同样是接缝。
- **判据**：能把"对外接口清单"列全（知道 hook 哪些点）。

### 1.5 init_array
```bash
readelf -d target.so | grep INIT_ARRAY
```
比 `JNI_OnLoad` 更早；加固 so 的解密 / 反调试 / 环境校验常藏于此。

### 1.6 一句话速查
```bash
file target.so
readelf -h -S -l -d -r target.so
readelf --dyn-syms target.so | grep Java_
strings -a target.so | grep -iE "key|salt|cipher|aes|gcm|init|ptr|frida|assets|sm4"
```

## 2. 静态工具链

### 2.1 GNU binutils
```bash
file                                    # 架构 / 类型
readelf -h/-S/-l/-d/-r                  # 头 / 节 / 段 / 动态 / 重定位
readelf --dyn-syms                      # 动态符号
objdump -d --start=0x... --stop=0x...   # 反汇编（已知范围）
strings -a                              # 全文字符串
```
> ARM64 下 objdump 可读性不如 capstone；大 SO 全量 objdump 会爆炸，**先定范围再反汇编**。

### 2.2 capstone（Python 主力）
```python
import capstone
md = capstone.Cs(capstone.CS_ARCH_ARM64, capstone.CS_MODE_ARM)
md.detail = True
for i in md.disasm(data[addr:addr+length], addr):
    print(f"{i.address:#x}: {i.mnemonic} {i.op_str}")
```
- 函数长度：相邻导出符号地址差，或 `st_size`。
- 常见模式：`STP x29,x30` = 函数序言；连续 `ldr [x_base,#off]` = 查表（白盒）；`adrp+add/ldr` = 取字符串 / 常量。

### 2.3 IDA / Ghidra
- **IDA**：函数边界 / xref 还原省力；对强混淆（OLLVM、VMP）差。
- **Ghidra**：免费；ARM64 表驱动（白盒）稍好；脚本批量改名。
- 大 SO 建议：IDA 定位 `bl` 目标 → 反编译看数据流 → 命中外部资产即转动态。

### 2.4 静态 → 动态 决策
| 问题 | 静态可答? |
| --- | --- |
| 函数在哪、叫什么 | ✅ readelf + 反汇编 |
| 调了哪些外部 API | ✅ `bl` + 导入表 |
| 输入→输出是什么变换 | ❌ 需运行（白盒 / 加密） |
| 密钥 / 盐值到底是什么 | ❌ 运行时才产生 |

## 3. 静态判据（测到什么算完成）

| 分析点 | 静态判据 | 若不满足 |
| --- | --- | --- |
| 接缝清单 | 导出 / JNI / 注册表全部列出 | 继续 `grep` / 反汇编 `JNI_OnLoad` |
| 壳 / 加固 | 节表 + 熵 + init_array 判定是否加壳 | 加壳 → 转运行时脱壳 |
| 数据流边界 | 能指出 TLS 栈 / 应用层加密函数**位置** | 复杂边界 → 动态确认 |
| 外部依赖 | 导入表 + 资源 / 文件字符串列全 | 补充 strings 特征 |
| 检测特征 | `strings` 命中的检测字符串**定位**到函数 | 动态看调用栈确认 |
| 目标函数 | 关键函数**地址 + 范围**确定（可反汇编） | 转动态 hook 验证 |

> 静态定**面**（位置 / 接口 / 特征），动态 / 模拟定**值**（密钥 / 变换结果 / 行为）。静态通常能定约 80% 的结构信息。

## 4. 坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 32/64 位搞错 | 反汇编乱码 | 先 `readelf -h` 看 `ELFCLASS` |
| 无偏移假设 | `data[addr]` 读错 | 只有 `p_offset==p_vaddr` 能直读，否则先转换 |
| 函数长度靠猜 | 反汇编溢出到邻函数 | 用相邻符号地址差 / `st_size` |
| `strings` 看漏 | 漏关键字符串 | 用 `strings -a`（含全段） |
| 白盒表当普通代码 | 看不懂 `ldr` 轮转 | 别硬看，转动态 / 模拟 |
| 强混淆死磕 | 时间黑洞 | 定位外部资产 / 转运行时观察 |

---

## 5. 适用范围

| 条件 | 静态可行度 |
| --- | --- |
| 未加壳、符号完整 | ✅ 高（能定位、能反汇编） |
| 加壳 / 抹符号 | ⚠ 只能定"有壳"，细节转运行时 |
| 强混淆（OLLVM/VMP） | ⚠ 定位 `bl`/字符串仍可，逻辑转动态 |
| 超大 SO（百 MB 级） | ❌ 不做全量反编译，只做定点 + 运行时观察 |
