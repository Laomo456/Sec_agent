## 四、方法论（可复现步骤）

### 4.1 砸壳（内存 dump，等效 bagbak）
```python
# 1. 探测模块基址
# frida 脚本: Process.enumerateModules() 过滤 .app 路径
# 主二进制: com_kwai_gif base=0x100298000 size=7061504 (首次启动时的值，每次 ASLR 变化)

# 2. 内存 dump（分块读避免 rpc 超限）
# frida 脚本:
rpc.exports = {
    readchunk: function(offset, size) {
        var p = ptr(base).add(offset);   # base = 模块基址
        return p.readByteArray(size);     # 注意: 不能用 Memory.readByteArray (frida17 坑)
    }
};
# Python 端: 循环 script.exports_sync.readchunk(offset, 700*1024) 写文件

# 3. 验证
# 文件头应为 cffaedfe (Mach-O 64)
# 检查 LC_ENCRYPTION_INFO_64 (cmd=0x2c) cryptid=0 = 已解密
```

### 4.2 抓取 API 请求（关键！）
```javascript
// 关键坑: hook NSURLSession 的 dataTaskWithRequest 抓不到快手请求！
// 必须 hook NSMutableURLRequest 的 -setURL: （快手走这条路）
var rq = ObjC.classes.NSMutableURLRequest;
var setUrl = rq['- setURL:'];
Interceptor.attach(setUrl.implementation, {
    onEnter: function(a) {
        var url = ObjC.Object(a[2]).absoluteString();
        console.log('[REQ] ' + url);
        // 带堆栈:
        var bt = Thread.backtrace(this.context, Backtracer.ACCURATE).slice(0, 30);
        bt.forEach(function(addr) {
            var s = DebugSymbol.fromAddress(addr);
            console.log('  0x' + addr.toString(16) + '  ' + (s.name||'') + '  [' + (s.moduleName||'') + ']');
        });
    }
});
```

### 4.3 attach 稳定性经验（重要）
| 方式 | 结果 |
|------|------|
| attach 重复注入的旧进程 | ❌ 卡死 `(os/kern) failure` / attach 超时 |
| frida spawn | ⚠️ 有窗口期，UI 卡转场（UITransitionView） |
| **tidevice launch + 立即 attach** | ✅ 最稳 |
| Python API attach | ⚠️ `ObjC is not defined`（**用 CLI**） |
| **frida CLI attach** | ✅ ObjC 可用，推荐 |

**规律**：快手 attach 窗口有限，多次注入后反调试触发。重启 app 可恢复。

### 4.4 frida 17 避坑清单
| 坑 | 解决 |
|----|------|
| `Memory.readByteArray` not a function | 用 `ptr.readByteArray(n)` |
| `Module.findExportByName(null, x)` not a function | 用显式库名 `libsystem_c.dylib` |
| `ObjC is not defined` (Python API) | 用 frida CLI（-l 加载 js） |
| `enumerateLoadedClasses` ownedBy bug | 用 `ObjC.classes` 或模块枚举 |
| `new File()` 读二进制 size undefined | 读文本可用，二进制走内存 |
| rpc.exports 方法名小写化 | readChunk → readchunk |
| `Interceptor.attach(objc_msgSend)` not a function | frida17 对 stub 符号的坑，避开 |

### 4.5 破签名算法方法论（本次会话核心经验 ⭐）

**核心思想：不要猜算法，直接 hook 哈希函数看输入。**

#### 第一步：确认哈希函数存在 + 真实符号名
```javascript
// 用模块枚举拿符号（findExportByName 在 frida17 有 null 坑）
var ccMod = null;
Process.enumerateModules().forEach(function(m) {
    if (m.name.indexOf('commonCrypto') !== -1) ccMod = m;
});
var exps = ccMod.enumerateExports();  // 列 CC_MD5/CC_SHA1/CC_MD5_Update 等
```

#### 第二步：hook 哈希入口抓输入（核心！）
```javascript
// CC_MD5(data, len, md) 一次性接口
Interceptor.attach(md5Addr, {
    onEnter: function(a) {
        var len = a[1].toInt32();
        if (len > 4 && len < 3000) {   // 过滤噪声（图片路径/设备查询都走 MD5）
            this.data = a[0].readUtf8String(len);
            console.log('[MD5] 输入: ' + JSON.stringify(this.data));  // 签名输入现形！
        }
    },
    onLeave: function(r) {
        // 读输出 hex，与 URL 里的签名值对比
    }
});
```

#### 第三步：同步 hook setURL 拿 URL（对照样本）
```javascript
// 同一时刻的 [MD5 输入→输出] 和 [URL 里的 sign] 一一对应
// 匹配上 = 算法确认；匹配不上 = 输入被截断/算法非 MD5
```

#### 第四步：多组样本验证（防偶然）
- 抓 ≥3 组 (输入, 输出) 对，全部匹配才算破
- **不要只信一组**（可能撞车）

#### 关键经验
| 教训 | 说明 |
|------|------|
| 先别猜拼接规则 | 盲试 8 种 MD5 组合全失败，浪费时间 |
| hook 哈希输入最直接 | 输入字符串就是签名素材，直接看到盐/排序 |
| 盐在输入尾部 | 733B 输入尾部 `...ver=14.623caab00356c` = 盐 `23caab00356c` 直接暴露 |
| 注意截断 | 日志切片 500B 导致算不出正确 MD5，要打全 |
| 过滤噪声 | 设备查询(MGCopyAnswer) / 图片路径 / 域名 SHA256 都是噪声 |
| 分步哈希要 hook Final | CC_MD5_Update 只看到部分输入，输出要 hook Final |
| 服务端校验行为可实测 | 改坏 sig / 改坏 NS3 分别测，确认校验哪些字段 |
| 参数编码敏感 | 服务端按解码后参数算签名，URL 传输要编码（%2C 等） |

#### 破 __NS_sig3 的教训（自研哈希）
- 不走 CommonCrypto（hook CC_MD5/SHA1/Final 均无对应 40hex 输出）
- 通过 ObjC 消息分发（跳板表 `b` 链），追到方法实现前无法确认
- 自研 160bit 哈希：纯运行时难破，需静态逆向（Ghidra/IDA）

## 五、签名逆向进展（到哪一步了）

### 5.1 已确认
- sign = 32 hex = **MD5 类哈希**（拼接规则自定义）
- __NS_sig3 = 40 hex = **SHA1 类**
- 生成位置：**ObjC 消息链**中（setURL: 调用前的字符串构造阶段）

### 5.2 运行时定位（已做到）
```
hook setURL: 拿堆栈 → 快手代码调用点（如 0x11419d900 运行时地址）
→ 反汇编该函数: 循环 bl objc_msgSend + adrp 全局表
→ 全局表是 ObjC 方法指针数组（非明文密钥）
→ selector 解析: setURL: / release（调用的是标准 ObjC 消息）
→ 结论: 签名在更早的 ObjC 方法里计算，藏在类方法表后
```

### 5.3 MD5 拼接验证（已做，全部失败）
- 8 种组合：原始顺序/排序/带 secretkey/值拼接/无分隔符 → **全部不匹配目标 sig**
- 结论：拼接规则含**自定义顺序或额外盐**，需静态分析还原

### 5.5 主接口 sig + 埋点 sig2 算法已还原（✅ 输入=输出 验证）

**算法（两套相同规则）：**
```
sig  = MD5( 全部参数按 key 字母序, "k=v" 无分隔符拼接 + 盐 "23caab00356c" )
sig2 = MD5( 同上规则 )   # 埋点接口（含 bodyMd5 参数）
```

**验证**（hook CC_MD5 抓到的实时输入）：
| 接口 | 输入 | MD5 输出 | URL 里的值 | 验证 |
|------|------|---------|-----------|:---:|
| /rest/n/spot | 733B 排序参数+盐 | 086a5aaf68e2b74cc20f76f02c89caf2 | sig=086a5aaf... | ✅ |
| /rest/n/log/client/realtime/collect | 577B 排序参数+盐 | 50247db2527007ec4675abcb853d1195 | sig2=50247db2... | ✅ |
| gdfp /kuaishou/data/t | 47B "50000fadd...timestamp" | 6e6fc4795d10eded01e8af2c8fbcbfe4 | sign=6e6fc479... | ✅ |

**Python 生成器：**
```python
import hashlib
SALT = "23caab00356c"
def gen_sig(params: dict, exclude=('sig','sig2','__NS_sig3','__NS_xfalcon')):
    body = ''.join(f'{k}={v}' for k, v in sorted(params.items()) if k not in exclude)
    return hashlib.md5((body + SALT).encode()).hexdigest()
```

### 5.9 破 NS3 完整尝试记录（全部失败 → 物理极限）
| 方法 | 结果 |
|------|------|
| 穷举 v1：8 哈希族 × 6 盐 × 排序输入 | ❌ 全灭 |
| 穷举 v2：输入格式变体（原始序/含xfalcon/URL编码值） | ❌ 全灭 |
| 穷举 v3：sig 值中间层复合（SHA1(sig+盐) 等） | ❌ 全灭 |
| 穷举 v4：xfalcon 有值变体（33/39 样本含值） | ❌ 全灭 |
| 穷举 v5：原始编码 query（%2C 未解码）| ❌ 全灭 |
| 分隔符变体（& / 换行 / 等号）| ❌ 全灭 |
| HMAC 家族 / 双哈希嵌套 | ❌ 全灭 |
| hook CommonCrypto（CC_MD5/SHA1/Final）| ❌ 无 40hex 输出 |
| hook libboringssl 导出（SHA1/EVP）| ❌ 无对应导出 |
| RIPEMD160 / SM3 小众哈希 | ❌ 全灭 |
| hook JIT 签名候选函数（动态定位）| ❌ **App 静默**（反调试检测 inline hook）|
| Stalker 追踪 | ⚠️ 能记录调用但拿不到返回值 |

### 5.10 破 NS3 的关键发现（最终证据链）
1. **`__NS_xfalcon` 不是空值**：稳定前缀 `HUDR_sFnX+35uAUNVsMPNK3DOP5wnti1Lc8Axjy5z88T61A==$TE_` + **每请求变化的加密后缀**（`1e0198fffe220d0f6f...` / `08178ee9e834...` / `a2bd2443429e...`）
2. **NS3 绑定 xfalcon 随机值** → 每次请求盐不同 → **离线生成数学上不可能**
3. **签名 URL 构造代码是 JIT 生成的**（0x1156d* 无模块区，每次启动地址变但结构稳定）
4. **hook App 自研代码 → App 静默**（停止发请求）；**hook setURL（ObjC 系统类）→ 正常**（v25 抓 50+ 签名 URL）
5. 签名 URL 调用栈稳定：`JIT 0x1156d1908 ← 0x1156d3894 ← 0x1156d39a0 ← CFNetwork`
6. 轻量监听（v17）App 正常发 145+ 请求；重型 hook（反汇编/backtrace）触发反调试静默

### 5.11 最终结论
- **本地（App 进程内）全破**：gdfp / 埋点 / sig 算法全部可控 ✅
- **服务端验证是最后防线**：__NS_sig3 = 自研 160bit 哈希 + 绑定含随机 xfalcon 的全部参数 → **无法离线生成**
- **实用方案**：App 实时抓完整签名 URL 原样重放（v25 工具，已验证可行）
- **完全破解需静态逆向 JIT 翻译器**（Ghidra/IDA 分析砸壳二进制，数小时-数天，独立大工程）
