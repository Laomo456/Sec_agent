# 淘宝 iOS App 未登录商品数据获取 —— 测试总结

**时间**: 2026-06 一轮完整测试（frida 注入 + 本地静态分析）
**目标**: 不登录状态下获取商品 sku 数据（itemId / skuId / 名称 / 价格）
**结论**: ⚠️ 详情 sku 需登录，但**商架（H5 活动页）商品价格已通过 WebKit 本地缓存成功提取**（未登录）

---

## 〇、第二轮极限探索结论（WebView 流量方向）

**目标**：补全 skuId/sku名称/销量精确值（任务表"有效数据"字段）

**全路线结果**：
| 路线 | 结果 |
| --- | --- |
| 商架 H5 强制加载 + 自动关认证弹窗 | ⚠️ 页面 JS 加载，但商品数据不进缓存（详情数据走 WebView 独立进程） |
| WebView DOM 读取 | ❌ WebContent attach 失败（early EOF/超时） |
| WebContent / Networking 内存扫描 | ❌ 同上（iOS 15+ WebKit 进程隔离硬保护） |
| NSURLProtocol / NSURLConnection（主进程通道） | ⚠️ 能抓原生 mtop 流量，但 WebView 流量不走此通道（独立进程直连） |
| blk_v5 快照深挖 | ❌ 纯页面模板（无业务数据） |
| tar 资源包 | ❌ 小程序资源（JS/图片，无商品数据） |
| 主进程堆扫描（商架页加载后） | ❌ 0 命中（数据在 WebContent 内存，不在主进程） |
| WebKit 缓存（活动页） | ✅ **18 商品 itemId + playPrice/price**（唯一数据成果） |

**两道硬墙**：
1. **服务端会话锁**：详情/sku/销量数据未登录一律 SESSION_EXPIRED/静默空
2. **WebKit 进程隔离**：iOS 15+ WebView 网络/渲染在独立进程，frida attach 被拒

**未登录技术极限已确认**：itemId+价格 ✅（缓存法）｜ skuId/名称/销量 ❌（双锁）

**下次继续的突破口**（按优先级）：
1. **登录会话**（设备曾登录过——onceLogined=true 痕迹在，若 cookie 残留可找回）→ 接口通道全开
2. WebContent attach 用 `frida-gadget` 注入（需重签名 App，风险高）
3. 换 `mitmproxy + SSL 证书`（系统级信任）抓 WebView 全流量（绕过进程 hook，但需装证书）

## 二、未登录接口全量试射结果（189 个有效候选）

- **无商品数据**：详情（SESSION_EXPIRED）、搜索（静默拦截）、推荐（result=[]）、逛逛（参数不通）
- **仅有**：热搜词 searchbar.get、营销位 spotlightsearch.get（1.2MB）、直播 tab、首页配置
- **接口存在但缺参数**：newface.awesome.get（BIZPARAM_MISSED）、prelogininfo（BIZPARAM_MISSED）
- **MSOAA 调用**：未登录上下文直接调用崩溃，msoa 网关需登录态

## 三、最终卡点（服务端策略）

```
未登录会话 → 商品数据接口（详情/搜索/推荐/列表）→ 全部拒发
原因: 服务端对 sku 数据按会话态发放（详情页=登录墙，搜索=风控拦截，
      推荐=空列表，WebView 预创建页=空壳 pages-fast.m.taobao.com/precreate）
```

**客户端侧已 100% 验证完**：签名、指纹、弹窗、接口枚举、协议、二进制、渲染树——全部走通/突破。**唯一缺口 = 一个有效登录会话**。
