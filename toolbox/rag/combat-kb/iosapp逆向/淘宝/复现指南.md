## 2. 验证签名通道（最关键一步）

**原理**：`TBDAIMtopClient` 是淘宝 iOS 的 mtop 客户端，`requestAsync` 请求自动附加 x-sign / mini-wua 签名（签名逻辑在 App 内，无需自研）。

**frida 脚本（最小可用）**：
```js
// tb_min.js —— 用 App 自身签名通道发任意 mtop 请求
setTimeout(function() {
    if (!ObjC.available) return;
    var cb = new ObjC.Block({
        retType: 'void', argTypes: ['object'],
        implementation: function(a) {
            var s = '';
            try { s = ObjC.Object(a).toString(); } catch(e) { s = String(a); }
            console.log('[RESP] ' + s.slice(0, 1500));
        }
    });
    // 参数: API名, 版本, needLogin, needWua, 参数Dict, 回调, 超时秒
    ObjC.classes.TBDAIMtopClient.requestAsync_version_needLogin_needWua_params_callback_timeout_(
        'mtop.taobao.regera.searchbar.get', '1.0', false, false, null, cb, 8);
}, 4000);
```

运行：
```bash
frida -U -f com.taobao.taobao4iphone -l tb_min.js -o out.txt
```

**预期**：返回热搜词 JSON（约 12KB）→ 签名通道可用。

**已知接口返回规律（用于后续判断）**：
| retCode | 含义 |
|---|---|
| `SUCCESS` + 数据 | 接口可用 |
| `FAIL_SYS_API_NOT_FOUNDED` | 接口名不存在 |
| `FAIL_SYS_BIZPARAM_MISSED` | 接口存在，缺参数 |
| `FAIL_SYS_PARSE_JSON_FAILED` | 需要 JSON 格式参数 |
| `FAIL_SYS_SESSION_EXPIRED` | 需登录会话 |
| `FAIL_SYS_USER_VALIDATE` | 触发验证（419） |
| 无 retCode + 极短响应 | 被静默拦截（RGV587 风控） |

## 3. 设备指纹伪造

**原理**：UTDID 存 UserDefaults（`UTDID` 键）+ sglocalstore.plist（风控存储）删除后 App 以新设备身份运行。

```js
// tb_fakefp.js —— 伪造设备指纹
setTimeout(function() {
    if (!ObjC.available) return;
    var st = ObjC.classes.NSUserDefaults.standardUserDefaults();
    var fake = 'UTDID-' + Math.floor(Math.random() * 1e10).toString(36);
    st.setObject_forKey_(fake, 'UTDID');
    st.synchronize();
    console.log('[+] 新 UTDID: ' + fake);

    // 删除风控存储（sglocalstore.plist）
    var libc = Process.getModuleByName('libsystem_c.dylib');
    var ge = new NativeFunction(libc.getExportByName('getenv'), 'pointer', ['pointer']);
    var home = ge(Memory.allocUtf8String('HOME')).readUtf8String();
    var fm = ObjC.classes.NSFileManager.defaultManager();
    var paths = [
        home + '/Library/Preferences/sglocalstore.plist',
        home + '/Library/Preferences/' // 也可整体处理，注意保留必要配置
    ];
    try { console.log('[+] sglocalstore 删除: ' + fm.removeItemAtPath_error_(paths[0], null)); } catch(e) {}
}, 4000);
```

**要点**：
- 删除后**必须杀掉 App 重启**（`frida -U -f` 重新 spawn 即可）
- 指纹变化后 419 惩罚会解除（但商品数据仍不下发，见第 7 节）

- 直接调 `MSOAWVService.requestService('msoa.taobao.detail.showsku@2.0', cb, wv, vc)` → 进程崩溃（未登录上下文）

- 结论：MSOAA 同样需要登录上下文

## 7. 结果汇总与卡点判定

**7.1 判定依据（为什么说"到极限"）**：
1. 342 个接口全量试射 → 无商品数据
2. 换场景/换参数/JSON 变体/换网关 → 全空
3. 指纹伪造 + 清 cookie + 弹窗 hook → 419 解除但仍拒发
4. 游客登录接口 → 不存在/缺参数
5. MSOAA → 未登录调用崩溃
6. WebView → 空壳预创建页
7. 渲染树观察 → App 界面未登录时无商品渲染（tab 栏而已）

**7.2 服务端行为总结**：
```
未登录会话：
  详情接口 → SESSION_EXPIRED（登录墙）
  搜索接口 → 静默拦截（无错误码）
  推荐接口 → SUCCESS 空列表
  H5 详情 → 转原生登录墙
  商品 sku → 一律不下发
```

**7.3 已确认的登录痕迹**（未读取值）：
- `sglocalstore.plist` 存在
- `prelogininfo` 返回 `onceLogined:true`、`lastLoginType:sms`、maskMobile `166****0708`
- 说明：登录凭证可能仍在 Keychain，但读取/使用属于"碰账号"范畴，测试未执行

## 8. 常见失败与原因（避免重复踩坑）

| 现象 | 原因 | 对策 |
|---|---|---|
| frida 脚本中文乱码 | Windows 控制台编码 | 脚本纯 ASCII |
| `Memory.readByteArray` 不存在 | frida 17 API 变更 | 用 `ptr.readByteArray(len)` |
| POSIX open 沙盒文件失败 | App 沙盒限制 | 用 NSFileManager 或 dump 到 Documents 后再用 |
| evaluateJavaScript block 报错 | frida Block 与 Swift block 兼容问题 | 传 NULL completion 只执行不取回 |
| attach 超时 | 淘宝反调试 | spawn 模式；attach 需快速部署 |
| requestService 调用崩溃 | 未登录上下文/参数格式未知 | 不要直接调，用 WebView JS 或登录态 |
| tidevice pull 失败 | AFC 权限 | 设备端直接分析，不拉文件 |
| 首页推荐 result=[] | 未登录分流 | 无解（服务端策略） |

## 9.5 商架商品价格提取（WebKit 缓存法 —— 已验证成功）

**原理**：淘宝 H5 活动页（天猫试用/聚划算 `tmall_yxpt` 系）未登录可浏览，页面数据响应会被 WKWebView 写入本地网络缓存（`NetworkCache/Version 16/Records/.../Resource/*-blob`）。**商品 JSON（itemId + playPrice/price/tryItemTitle）直接从缓存提取**，无需任何接口请求。

**步骤**：
1. 在 App 内打开任一商品活动页（天猫试用/聚划算/闪购——未登录即可，页面加载即缓存）
2. frida 脚本扫描 WebKit 缓存，找含 `itemId` 且 ≥5 个的 blob 文件：

```js
// 枚举缓存目录
var fm = ObjC.classes.NSFileManager.defaultManager();
var roots = [home + '/Library/Caches/WebKit/NetworkCache', home + '/Library/WebKit/NetworkCache'];
// 对每个 *.blob 文件：POSIX open/read → 字符串化 → 正则
var itemHits = txt.match(/(itemId|item_id|auctionId|"nid")["']?\s*[:=]\s*["']?\d{7,20}/g) || [];
var priceHits = txt.match(/[¥￥]\s?\d{1,4}(\.\d{1,2})?|["']price["']\s*:\s*["']?\d{1,4}(\.\d{1,2})?|sprice[^0-9]{0,20}\d{1,4}/g) || [];
// itemHits>=5 && priceHits>=5 → 商品缓存
```

3. 提取商品字段（已验证输出样例）：

```
--- 922373003785 ---
  "922373003785","salesSite":"19","tryItemTitle":" ","playPrice":"5","juId":"10031017565153",...
--- 936577808355 ---
  "936577808355","salesSite":"19","tryItemTitle":" ","playPrice":"0.6","juId":"10030983730294",...
```

**字段表**：
| 字段 | 含义 |
|---|---|
| itemId | 商品 id（18 个/页） |
| playPrice | 活动价（试用价，如 5 / 0.6） |
| price | 参考价（如 500 / 60） |
| tryItemTitle | 商品标题 |
| juId / activityId / activitySignId | 活动标识 |
| trackInfo | 曝光追踪（含接口路径 `tmall_yxpt_common.common_exp`） |

**已提取数据样例**（18 个商品）：922373003785(5元) / 904916847543(500元) / 941986824699(60元) / 922376391185(60元) / 797230283796(60元) / 580570621621(60元) / 921919504096(60元) / 907249627275(60元) / 651212402992(60元) / 1051769002659(60元) / 803637367794(60元) / 928370276167(60元) / 817994835109(60元) / 1056087813348(60元) / 1057015584169(60元) / 1052639570470(60元) / 864692798561(60元) / 936577808355(0.6元)

**注意**：缓存文件随页面浏览生成/过期，重复步骤 1 可刷新数据；`price` 提取正则需同时覆盖 `playPrice`/`price`/`sprice` 变体。
