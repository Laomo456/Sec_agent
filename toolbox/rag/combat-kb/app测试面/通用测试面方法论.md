# App 通用测试面 — 方法论清单

> 适用于: 手游/App 全量安全测试（黑盒优先，白盒辅助）
> 原则: 每个面先确认"有无状态/逻辑"再测——无状态面（CDN/静态）直接跳过

---

## 〇、测试总流程

```
1. 资产盘点: APK/dex/so/脚本/域名/接口（静态提取）
2. 面分类: 客户端组件 / 存储密钥 / WebView / 服务端接口 / 更新链 / 注入
3. 逐面测试（下表）→ 每面记录: 方法 + 证据 + 判定
4. 严谨验证: 疑似漏洞必须排除假象（同请求×3 对比/对照组）
5. 归档: 测试面文档 + 可提交漏洞报告（SRC 标准）
```

## 一、客户端组件面

### 1.1 导出组件（Activity/Service/Receiver/Provider）
```
方法:
  1. dumpsys package <pkg> 或反编译 manifest → 组件清单
  2. 逐个 am start -n <pkg>/<component>（无 SecurityException = exported）
  3. 传可控参数（--es url/--ei id）观察行为 + logcat
  4. Provider: content query --uri content://<authority>/
判定漏洞:
  ✅ exported + 敏感操作（加载任意 URL/文件读写/支付）→ 深链/组件滥用
  ❌ exported 但仅 UI 展示 → 低危/不收
关键项:
  intent-filter VIEW+BROWSABLE 的组件（深链入口）、fileprovider（路径配置）
```

### 1.2 深链/Intent 注入
```
方法:
  1. 提取所有 scheme/host/path（manifest 字符串池 UTF-16）
  2. am start -a android.intent.action.VIEW -d "<scheme>://<host><path>"
  3. 参数注入: 额外字段/畸形值 → logcat 崩溃/行为差异
判定漏洞:
  ✅ 深链触发敏感功能（支付/登录替换/文件访问）
  ✅ 参数可控进 WebView/file 操作
```

### 1.3 WebView JS 接口
```
方法:
  1. 静态: dex 找 addJavascriptInterface / JSBridge / @JavascriptInterface
  2. 动态: logcat 找 LuaJavaBridge/callJavaStaticMethod 调用链
  3. 内容可控性: 接口方法是否接收 WebView 页面传入参数
判定漏洞:
  ✅ JS 接口暴露 + 页面内容可控（远程页面/注入点）→ 任意 Java 调用
  ✅ 接口含敏感方法（文件/短信/命令）+ 无白名单域校验
```

## 二、存储与密钥面

### 2.1 明文存储
```
方法:
  1. adb 拉取: shared_prefs/*.xml、databases/*.db、files/、app_webview/
  2. 审 token/cookie/密码/支付缓存/账号信息
判定漏洞:
  ✅ token/会话明文可读（其他 App 可读前提: 外部存储或备份可提取）
  ⚠️ 内部存储自读 = 常规（非漏洞）——需结合备份/沙箱逃逸
```

### 2.2 硬编码密钥/弱加密
```
方法:
  1. so: 搜常量（XXTEA delta 0x9E3779B9/AES S盒/固定 IV/key 串）
  2. lua/dex: 搜密钥字符串/base64 长串/自研加密函数
  3. 验证: 密钥能否解密受保护数据（热更/协议/本地配置）
判定漏洞:
  ✅ 硬编码签名 key → 伪造客户端签名（服务端校验缺失时）
  ✅ 固定加密密钥解密敏感数据
  ❌ 找不到 ≠ 漏洞（需证明利用路径）
```

## 三、内存与逆向面（资产级）

```
方法: frida/hook 管线 → 明文脚本/函数调用捕获
判定:
  ❌ 代码可逆向/内存可改 = 所有 App 常态（SRC 不收）
  ✅ 逆向产物用于: 提取真实接口/密钥/协议 → 转测服务端
```

## 四、服务端接口面（重点）

### 4.1 接口发现
```
方法:
  1. 客户端脚本/JS 全量提取（比盲猜 fuzz 高效 10 倍）
  2. 域名+路径模式枚举（版本化对象）
  3. 网关特征: 错误码体系（605/606/607/999 类）识别白名单路由
```

### 4.2 未授权/越权（最高命中率）
```
方法: 逐个接口无凭证直打 → 对比登录态差异
判定漏洞:
  ✅ 匿名可读用户数据（uid 遍历 = IDOR）
  ✅ 参数替换他人 ID（水平越权）
  ✅ 管理接口无鉴权
```

### 4.3 注入（先判定有无输入通道！）
```
前置判定（关键）:
  1. 参数是否进 SQL: 行为证据（自增 id/GROUP BY/持久化）
  2. 参数类型: 数字闸门（非数字 999 类）/字符串白名单/被忽略
  3. 通道结论: 数字闸门 = 输入空间压缩为数字 → 注入物理不可达
方法（有通道才测）:
  SQLi: 报错/布尔/时间盲注 + 编码绕过 + 污染 + ORDER BY
  SSTI/LDAP/命令: 仅当参数是字符串且格式宽松
严谨验证:
  ✅ 同参数 3 次请求对比（排除数据本身乱序假象）
  ✅ 算术注入（1-1 → 999 证明应用层强转）
```

## 五、网关/中间层面

```
方法:
  1. 指纹: Server 头/安全头模板（Spring Security 全套 = Spring Boot）
     /链路头（ntes-trace-id 类 = 自研微服务）
  2. 管理端点: /actuator/* /env /health /swagger /druid /jolokia
  3. 路由绕过: // ./ %2e%2e %00 ;.js ..; 大小写 编码
  4. 方法面: TRACE/CONNECT/override 头/CL.TE 走私
  5. 参数解析差异: 污染/大小写/数组
判定:
  ✅ Actuator 暴露 = 配置泄露（高）
  ✅ 走私/路由差异 = 网关绕过（高）
  ✅ 业务转发无鉴权 = 架构级（中——最有价值提交点）
```

## 六、更新/热更链面

```
方法:
  1. 清单接口枚举（hotfix_list 类）+ 版本历史全量拉取
  2. 内容审查: 明文（直接看）/密文（找 key）
  3. 篡改路径: 校验方式（md5/签名/HTTPS）+ 中间人可能性
判定漏洞:
  ✅ 无签名校验热更 = 任意代码执行（高）
  ✅ 明文热更含敏感配置
  ❌ 密文+md5+HTTPS 三重防护 = 无面（死资产）
```

## 七、有效/无效测法总结

### ✅ 有效（命中率高）
| 测法 | 命中案例 |
|---|---|
| 客户端资产 → 真实接口提取 → 未授权测试 | IDOR/PII |
| 行为证据判定数据库存在性 | 注入面评估 |
| 响应头指纹 → 框架/网关判定 | 架构级漏洞定位 |
| 同参数×3 对比（严谨验证） | 排除排序假象 |
| 数字边界探测 → 校验器逆向 | 注入通道判定 |

### ❌ 无效（避免浪费）
| 测法 | 原因 |
|---|---|
| 静态 CDN 文件注入测试 | 无状态无面 |
| 盲猜路径 fuzz（大词表） | 应从客户端提取 |
| 数字闸门参数反复变换 payload | 输入空间已压缩 |
| 对"被忽略参数"执着绕过 | 先验证参数是否生效 |

## 八、SRC 提交判定速查

```
✅ 收: 未授权访问/越权（IDOR/PII）/导出组件滥用/WebView JS 滥用/
       硬编码签名密钥/无签名热更/Actuator 泄露/深链敏感功能
❌ 不收: 代码可逆向/内存可改/接口存在/反调试可绕/匿名可读公开资源
判断核心: 漏洞 = 服务端/组件"应该校验却没校验"——不是客户端可被操纵
```

## 九、内核工具面（strace/ss——绕过用户态 hook 的反检测）

```
适用: 用户态 frida hook 零收获/游戏反用户态检测时
方法:
  1. ss -tnp | grep pid=<P> —— 网络端点全景（一键枚举全部连接）
     → 新资产: 游戏服 IP:端口/推送通道/明文 HTTP 端点
  2. strace -f -p <PID> -e trace=connect —— 连接目标收集（含 IPv6）
  3. strace -f -p <PID> -e trace=sendto -s 3000
     → 明文 HTTP 全量捕获（POST 头+body——Host/路径/敏感字段）
     → 私有协议帧观察（长度前缀/seq/ack）
  4. strace 读 /proc/<PID>/status TracerPid（反调试自检）
判定漏洞:
  ✅ 敏感 PII 明文 HTTP 传输（邮箱/UDID/设备指纹——strace 直接可见）
  ✅ 新端点发现（推送/游戏服）→ 转新测试面
  ⚠️ strace 附加可能被反调试进程检测（推送等）——一次抓完即撤
关键:
  明文上报接口常为 "POST / + Host 头路由"（Gas3-Clientlog 类）
  → 抓完整 Host 才可重放（PC 重放需同 Host+同格式）
```

## 十、TCP 私有协议面

```
方法:
  1. strace sendto 抓帧（长度前缀 [4B]+cmd+seq 模式识别）
  2. seq 分析: 恒定步进（如 +0x3e8）= 可预测（防重放评估）
  3. 业务帧触发: 需游戏内操作（商城/领取）——心跳帧无价值
  4. 重放测试: 原样重发捕获帧 → 服务端是否校验 seq/防重放
判定漏洞:
  ✅ 重放成功 + 业务效果重复 = 缺防重放（重复领取/操作）
  ✅ payload 明文可改 = 协议篡改面
  ❌ payload 加密 + 无 key = 重放无意义（内容不可控）
```

## 十一、攻击面穷尽清单（避免重复劳动）

```
测试前对照——全部测过才算收尾:
  1. H5 网关（接口/注入/方法/路径/网关层）
  2. 更新链（清单/版本遍历/热更/下载器）
  3. 客户端组件（exported/深链/Provider/JS 桥）
  4. 存储密钥（明文/备份/硬编码）
  5. 服务端接口（登录态/未授权/经济系统）
  6. 网络全景（ss 全端点 → 逐个探测）
  7. 推送通道（私有协议/内容注入）
  8. TLS/HTTPS（SNI 枚举/多实例 SSL hook）
  9. 明文上报（strace 捕获——最容易出新漏洞）
  10. 存量流量（已捕获数据再分析——免新操作）
  11. 游戏内 H5（Lua URL 全提取——排除证书噪声）
  12. 经济逻辑（Lua 静态——服务端主导=无信任点）
边界: 仅测第一方资产（游戏域/服务器）——第三方（音乐/电商/分享）不测
```
