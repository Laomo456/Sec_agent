# 字幕与音源对齐

> 更新时间：2026-07-28

## 一、字幕生成流程

### 整体流程
```
TTS生成MP3 → 音频合并为audio.wav → VAD检测说话区间 
→ 文案按VAD段分配 → 逗号拆分短句 → SRT生成 → 烧录
```

### 关键脚本
- `D:\ai动画\第二期\rebuild_all_srt.py` — 读取各项目文案.txt + audio.wav → 生成subtitle.srt
- `D:\ai动画\第二期\build_final_subs.py` — 合并各段SRT → 烧录到最终成品

### 文案格式
```
每行=一条字幕，逗号不拆分
一行显示一个时间段
```
文案中的逗号（`，`）仅用于原文分隔，**不**拆成多条字幕。
超出VAD段数的行，平分最后一段的时间。

## 二、VAD 说话检测

### 工具
- **FunASR fsmn-vad**（`iic/speech_fsmn_vad_zh-cn-16k-common-pytorch`）
- ModelScope缓存：`D:\yy\modelscope\models\iic--speech_fsmn_vad_zh-cn-16k-common-pytorch`

### 参数
| 参数 | 值 | 说明 |
|:----|:---:|:-----|
| 合并间距 | 300ms | <300ms的停顿视为连续说话 |
| 最短字幕 | 1.5s | 不足则扩展 |
| 最长字幕 | 15s | 超过则截断 |

### VAD vs 文案行数处理
- **VAD段 ≥ 文案行数**：一对一分配
- **VAD段 < 文案行数**：前 N-1 段一对一，剩余行平分最后一段

### VAD使用代码
```python
from funasr import AutoModel
vad = AutoModel(model='iic/speech_fsmn_vad_zh-cn-16k-common-pytorch', 
                disable_update=True, device='cpu')
r = vad.generate(input='audio.wav')
# 合并<300ms的段
merged = [r[0]['value'][0]]
for s in r[0]['value'][1:]:
    if s[0]-merged[-1][1] < 300:
        merged[-1][1]=s[1]
    else:
        merged.append(s)
segs = [(s/1000,e/1000) for s,e in merged]
```

## 三、音频与文案对齐

### 音频来源
- MP3文件存放在各项目的 `语音\` 目录
- MP3文件名即该段TTS文本内容
- 所有MP3文件合并为 audio.wav（VAD在此检测）

### 对齐规则
1. **文案顺序必须与音频播放顺序一致**
2. MP3创建时间顺序 ≠ 音频播放顺序
3. 每个MP3对应一个VAD段
4. 如果一行文案被拆成多行（如长句拆成多个字幕），它们共享同一个VAD段的时间

### 踩坑：顺序错位
文案顺序跟MP3创建时间顺序不同会导致字幕时间完全对不上。
**解决方法**：文案按MP3创建时间排序，或确保audio.wav的拼接顺序与文案一致。

```powershell
# 查看MP3创建顺序（音频实际播放顺序）
Get-ChildItem '语音\' | Sort-Object CreationTime | ForEach-Object { $_.BaseName }
```

## 五、字幕烧录

### FFmpeg 注意事项
Windows路径中的 `:`（盘符）会被ffmpeg当成参数分隔符。

**解决方法**：将SRT文件放到项目目录，使用相对路径：
```python
import subprocess
d = r'D:\ai动画\第二期\中\总结'
srt_name = 'burnsrt.srt'  # 放在输出目录，用相对路径
r = subprocess.run([ffmpeg, '-y', '-i', '最终成品_clean.mp4',
    '-filter_complex', f'subtitles={srt_name}',
    '-c:a', 'copy', '最终成品.mp4'], cwd=d)
```

## 六、音源指纹匹配（已弃用）

**尝试过的方法**：
- 波形互相关：失败（TTS混在录屏噪声中）
- MFCC匹配：失败（所有匹配点都在0s处）
- 谱图余弦相似度：失败（相似度仅0.01-0.07）

**结论**：TTS音频叠加在屏幕录制背景噪声上时，指纹匹配不可靠。
**推荐方案**：VAD检测+文案顺序分配。
