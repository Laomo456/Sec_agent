# 数据恢复功法

> 适用于 Windows NTFS：`Remove-Item -Force` 删除的文件恢复
> 原理：数据仍在磁盘上（仅 MFT 标记为已删除），未被覆盖就能恢复

---

## 方案 A：PhotoRec（文件雕刻 · 不保留文件名）

```powershell
# 工具：testdisk-7.3-WIP.win.zip
# 运行 photorec_win.exe
# 选 PhysicalDrive0 → 目标分区 → NTFS → Whole → 输出目录
# 恢复文件在 recup_dir.1/2/3... 里，按修改时间排序找人
```

## 方案 B：C# MFT 深度扫描（保留文件名）

**环境：** .NET Framework 2.0+（Windows 自带 `csc.exe`）

### 步骤

#### 1. 获取分区参数
```powershell
Get-Partition -DiskNumber 0 | Select-Object PartitionNumber, DriveLetter, Offset
# 记下目标分区的 PartitionNumber 和 Offset
```

#### 2. MFT 解析核心逻辑
```
打开 \\.\PhysicalDrive0 → 读启动扇区
→ 计算 MFT 位置（簇号 × 每簇扇区 × 512）
→ 遍历 MFT 条目（每 1024 字节，搜索 "FILE" 签名）
→ 检查 Flags[0x16] 位 0 → 0=已删除
→ 解析 $FILE_NAME(0x30) → 取文件名
→ 解析 $DATA(0x80) → 取文件内容
→ 写入磁盘
```

#### 3. MFT 关键偏移

| 偏移 | 大小 | 说明 |
|------|------|------|
| 0x00 | 4 | "FILE" 签名 |
| 0x14 | 2 | 第一个属性偏移 |
| 0x16 | 2 | Flags（位 0=使用中） |
| 启动扇区 0x40 | 1 | MFT 条目大小（负值 = 2^(-n)） |

**$FILE_NAME 属性(0x30)：**

| 偏移 | 说明 |
|------|------|
| +0x08 | 非驻留标志（1=数据在外部） |
| +0x14 | 内容偏移（相对属性头） |
| 内容+0x00 | 8字节父目录引用 |
| 内容+0x40 | 文件名长度 |
| 内容+0x42 | 文件名（Unicode） |

**$DATA 属性(0x80)：**

| 偏移 | 说明 |
|------|------|
| +0x08 | 非驻留标志 |
| +0x10(驻留) | 数据长度 |
| +0x14(驻留) | 数据偏移 |
| → | 直接从 MFT 条目复制数据 |

#### 4. 编译运行
```powershell
C:\Windows\Microsoft.NET\Framework\v2.0.50727\csc.exe /nologo /out:recover.exe recover.cs
.\recover.exe
```

## 方案 C：卷影副本 VSS（需有历史快照）

```powershell
# 创建卷影副本
Invoke-CimMethod -ClassName Win32_ShadowCopy -MethodName Create -Arguments @{Volume = "D:\"}
# 挂载
cmd /c "mklink /d C:\shadow \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\"
# 恢复
Copy-Item "C:\shadow\path\to\file" "D:\restored\"
```

## 注意事项

1. **删除后立即停止写入**该磁盘，防止数据被覆盖
2. 挂载了 `PhysicalDrive0` 后必须 `CloseHandle`，否则磁盘无法安全弹出
3. **大文件（非驻留数据）**需要跟 Cluster Chain 链，不在 MFT 条目内，恢复更复杂
4. C# 程序每次修改后需用 `csc.exe` 重新编译
5. PowerShell `Add-Type` **不会跨调用保留**（每个 bash 调用是独立进程）
