# 逆向习惯（自评/2026-09-09）

## 工具偏好

- **轻量 CLI 优先**：rizin > IDA，capstone/Python > JEB，unidbg > 真机
- **不要 GUI 重型工具**：IDA/JEB 占资源、分析慢，除非必要不用
- **AI 可用**：装工具考虑我（Reasonix）能否直接调用——Python CLI、Java CLI 优先
- **不装没实战过的工具**：知识库只写验证过的东西，不写空中楼阁
- **缺工具你自己装**：如果发现缺了什么，先判断确实缺再装，不用每次问我

## 工作流习惯

- **不要新建文件/文件夹**：桌面整理靠删除中间产物，不靠分类归档
- **散件放在桌面**：不搞多层目录结构，顶级目录名短
- **中间产物随手删**：exp*.js、临时脚本、可重生的大目录（jadx_out、blutter_out、apk_extract）跑完就删，不堆积
- **保留 APK 样本 + 最终报告 + 核心脚本**：这三样留着当战绩

## 分析风格

- **从外到内**：先看 ELF 头/NEEDED/导出表 → 再看反汇编 → 最后模拟执行
- **遇到卡点先找根因**：不跳过问题，追寄存器值/GOT 槽/重定位直到定位
- **企业级慢慢来**：加固/白盒库不追求一次跑通，一步步补环境
- **实战验证闭环**：拿到密钥只是开始，要跑通"加密→密文→解密→原文"才算数
- **宁可拆成脚本**：capstone 反汇编、LIEF 查段/r2 列导出——全用 Python/CLI 脚本，不留手工作业

## 本地静态逆向工具链（只列轻量工具，不用大家伙）

> 基本原则：**能 CLI 搞定就不开 GUI，能静态读就不动态跑，能在 Windows 本地完成就不依赖设备。**

### 工具清单（按使用频率排序）

#### ① rizin — CLI 主力（so/ELF 通杀）

```
D:\逆向工具\rizin\rizin-win-installer-vs2019_static-64\bin\
├── rizin.exe       交互式反汇编/调试/hexpatch
├── rz-bin.exe      列导出表/段/NEEDED/字符串（静态分析第一刀）
├── rz-asm.exe      汇编/反汇编（arm64/x86）
├── rz-find.exe     搜索字节/字符串/指令
└── rz-gg.exe       gadgets 搜索
```

典型用法：
```
rz-bin -E libxxx.so             列导出函数名+地址（JNI 函数一眼定位）
rz-bin -l libxxx.so             列 NEEDED 依赖 so
rz-bin -z libxxx.so             列字符串常量
rizin -q -c "s 0x367f20; pd 40" libxxx.so   反汇编指定函数
rizin -Ah -c "axt @0x36b98c" libxxx.so     搜交叉引用
```

> 对标 IDA 的交互式反汇编 + hexpatch，但纯 CLI、55MB 单 exe、秒开 12MB so。

#### ② LIEF + capstone（Python 脚本） — 批量/自动化

```python
import lief, capstone
b = lief.parse("libxxx.so")
print([l.name for l in b.libraries])              # NEEDED
print([r.type for r in b.relocations])             # 重定位类型/数量
print([hex(s.virtual_address) for s in b.segments])# LOAD 段

md = capstone.Cs(capstone.CS_ARCH_ARM64, capstone.CS_MODE_ARM)
code = open("libxxx.so","rb").read()[0x367f20:0x367f20+200]
for i in md.disasm(code, 0x367f20):
    print(f"0x{i.address:x}: {i.mnemonic} {i.op_str}")
```

什么时候用：需要自动化（批量查 GOT 槽/段结构/跨函数），或 rizin 的 aaa 太费时的场合。

#### ③ jadx — dex → Java 源码

```
D:\逆向工具\jadx\jadx-1.5.5\bin\jadx.bat -d out classes.dex [classes2.dex ...]
```

- 脱壳后的 dex、看 native 方法签名（参数类型/个数）
- 只看 native 声明和上层调用链，不耗在 Java 壳代码里
- 7K+ 类的 APK 也能 2 分钟内反完（7435/8978 的错误正常，不影响关键类）

#### ④ unidbg — JVM 里模拟执行 so（不开真机）

```
D:\逆向工具\unidbg\
├── mvnw.cmd   Maven wrapper（自动下依赖）
├── pom.xml    0.9.10-SNAPSHOT
└── unidbg-android/   Android 模拟执行
```

编译运行：
```
mvnw.cmd -f D:\逆向工具\unidbg\pom.xml install -DskipTests -Dgpg.skip=true
```

场景：so 有 JNI 入口，算法不透明（白盒/混淆），静态读不动，但也不想开模拟器跑 frida。

> **注意事项**：这个 fork 的 HookStatus.RET/LR 语义与标准版相反——`RET(emu, x)` 把 x 当 PC 跳，要用 `LR(emu, x)` 设返回值。

#### ⑤ Blutter — Flutter 专用（非通用 so 工具）

```
blutter.py libapp.so outdir  （需英文路径，不能有中文！）
→ outdir/pp.txt（字符串池：域名/密钥/Token）
→ outdir/asm/*.dart（伪汇编）
→ outdir/blutter_frida.js（frida 脚本模版）
```

Dart AOT 的 libapp.so 不是 JNI so，Blutter 静态输出字符串池（pp.txt）就够了，通常不用执行。

#### ⑥ apktool — APK 解包/解 so

```
apktool d app.apk -o out -f   解包拿 so/Manifest
```

只用 d 解包功能，不重打包（重打包签名麻烦，不如直接用设备装原包）。so 从 `lib/arm64-v8a/` 或 `apktool` 提取。

#### ⑦ pycryptodome — 密钥验证（Python 收尾）

```python
from Crypto.Cipher import AES
c = AES.new(KEY, AES.MODE_CBC, IV)
plain = unpad(c.decrypt(base64.b64decode(data)), 16)
```

拿到密钥/IV 后第一件事就是写 Python 脚本验证"加密→密文→解密→原文"闭环。

### 场景路线（具体怎么干）

```
① 拿到 so 第一件事：rz-bin -E 导出函数
   → 看到 JNI 规则函数名（Java_xxx_xxx）→ 这是给 Java 调用的入口
   → 有 pp+0x 前缀的 → Blutter 场景（Flutter）
   → 全是 std::/void/静态地址 → 可能壳 so

② 决定是否静态可解：
   字符串池里有密钥明文字符串（硬编码）→ pycryptodome 直接干
   密钥不在字符串里（运行时算/读文件）→ unidbg 模拟执行

③ Flutter 场景不纠结：
   不上 unidbg（libapp.so 不是 JNI so）
   Blutter pp.txt 搞定

④ unidbg 场景（JNI 算法/白盒）：
   rz-bin -E 导出表 → 复制 JNI 函数符号名
   LIEF 查 NEEDED → 确认 AndroidResolver 能提供
   unidbg loadLibrary → callJNI_OnLoad → 补 Jni 回调 → 调目标函数
   如果 return null → 缺回调实现（看 UnsupportedOperationException 提示）
   如果崩内存 → GOT 懒绑定没解（HookZz replace + 修 GOT 槽）
   如果返回结果 → pycryptodome 验算正确性

⑤ 加固壳（梆梆/爱加密）：
   dex 加密/空壳 → frida-dexdump 运行时脱壳（唯一需要设备的步骤）
   lad exec.so 可能在 assets/ijiami_lib/ → 要 BlackDex 或手动提
   脱壳完按 ①-④ 路线继续
```

## 踩过才记住的坑

- Blutter 必须纯英文路径（junction 都救不了，Python resolve() 穿透）
- houdini 转译下 Interceptor hook 无效 → 内存扫描替代
- Dart HttpClient 不走系统代理 → 内存扫描抓明文
- 这个 unidbg fork 的 HookStatus.RET/LR 语义与标准版相反（RET 把第二参数当 PC 跳）
- AES 模式先试 CBC（package:encrypt 默认）
- nsv11 状态残留 → killall r3 再重启
- **反汇编脚本必须显式指定目标 `.so`**：脚本里硬编码目标文件（我为 libsecsdk 写的脚本被复用到别的库）→ 你看到的"另一个库的结论"其实是第一个库；**跨库复用脚本先校验目标**（连错两次，教训）。
- **必须从"已知指令边界"起反汇编**：用"任意 `addr-0xNN`"当起点会**错位**成"看似合理实则假"的指令（把假代码当真结论）→ 从函数头(`stp x29,x30`/`paciasp`)或 `.text` 起点线性起。
- **密码公式必用"运行时数据"验证闭环**：`磁盘密文 ↔ 运行时明文` 全中才算对（"变换 A 的结果能被逆变换 B 还原"）；日志/回显是字符串时别整行 `split`。
- **结论要标"拟真 vs 真机"**：Qiling/unidbg 结论≠真机结论（真机多 maps/线程/注入痕迹）；**未真机验证就明说**，别当"能过"。
